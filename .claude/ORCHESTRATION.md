# 오케스트라 운영 매뉴얼 (Opus 4.7 메인)

> 본인(메인 에이전트)이 따를 운영 규칙. 사용자 요청 → 어느 서브에이전트로 위임할지 → 검증·구현 단계 관리.

---

## 1. 메뉴 → 에이전트 매핑

| 사용자 요청이 닿는 메뉴 | 호출할 에이전트 |
|---|---|
| 병의원/법인/영업사원, 코드 생성, 승인 | `biz-user-mgmt` |
| 통계 제출처, 사업자등록증 ZIP, 신규/이관, 월별 제출, 미매핑 | `biz-submission-routes` |
| 요율 업데이트, 코프로모션 예외 | `biz-rates-mgmt` |
| 정산내역서 업로드, 검수, 컬럼매핑 | `biz-settlement` |
| 필터링 현황·플로우, 제약사→상위법인 매핑, 법인×제약사 추가수수료, 알림톡 | `biz-filtering` |

복합 작업(여러 메뉴 걸침) — 메뉴별로 쪼개서 각각 호출. 의존성 있으면 순서대로.

---

## 2. 5단계 워크플로우 (반드시 준수)

```
사용자 요청
   ↓
[1] 메인이 메뉴 분류 + 서브에이전트 선택
   ↓
[2] 서브에이전트에 mode=verify 호출 → 검증 계획 수령
   ↓
[3] 메인이 직접 검증 실행 (Bash, Read, grep, build 등)
     - verify 체크리스트의 모든 항목을 실제로 돌려봄
     - 위험·미정 사항을 사용자에게 확인 (필요 시)
   ↓
[4] 100% 통과 시 → 서브에이전트에 mode=implement 호출
     실패 시 → 서브에이전트에 verify 재작성 지시 (원인 + 개선 방향 첨부)
   ↓
[5] implement 결과 받으면 메인이 회귀 검증
     - 빌드, 핵심 회귀 테스트, 영향 받는 파일 diff review
     - 통과 시 → 사용자에게 변경 요약 보고
     - 실패 시 → 서브에이전트에 수정 지시 (다시 [4]로)
```

**핵심 원칙: 검증 통과 없이 구현 시작 금지.**

---

## 3. 메인이 실행할 검증 도구

verify 체크리스트 항목별로 메인이 직접 돌릴 수 있는 명령:

| 검증 항목 | 도구 |
|---|---|
| TypeScript 타입체크 | `npx tsc --noEmit` (환경 따라 실패 가능) |
| Prisma 스키마 일관성 | `npx prisma validate` |
| 빌드 | `npm run build` (시간 오래 걸림 — 필요시만) |
| 회귀 grep | `grep -rn` 으로 영향 받는 호출부 점검 |
| API 시그니처 호환성 | 호출부 grep + diff |
| DB 마이그레이션 멱등성 | SQL의 `IF NOT EXISTS` 확인 |
| 사이트 의존성 | `import` 그래프 grep |

---

## 4. 사용자 보고 포맷

작업 라운드마다:
```
## ✅ 완료
- (구현된 것)

## 🔍 검증 결과
- (메인이 돌린 검증 통과/실패 요약)

## ⏭ 다음 단계
- (이어할 것)

## ❓ 사용자 확인 필요
- (있으면)
```

장황하게 하지 말 것. 사용자는 "이거 됐어/안됐어"가 알고 싶다.

---

## 5. 진행상황 갱신

매 라운드 끝에 `.claude/PROGRESS.md` 갱신:
- 메뉴별 큐 (진행중/검증대기/완료)
- 작업 로그 한 줄 추가

---

## 6. 금지 사항 (메인)

- **검증 없이 implement 호출** — 절대 X
- **verify 산출물에 코드 변경이 섞였을 때 그대로 통과** — 서브에이전트에 재작성 지시
- **DOMAIN_VIOLATION 무시** — 다른 메뉴 영역 건드리면 즉시 롤백
- **사용자 미확인 SQL 실행** — 사용자에게 가이드만 줌
- **파일 직접 수정** — 메인은 기본적으로 위임, 단순 진행상황·로그·이 매뉴얼만 수정

---

## 7. 토큰 절약 (Sonnet 4.6 위임)

- 모든 코드 작성·읽기·수정은 서브에이전트(Sonnet)에 위임
- 메인(Opus)은 라우팅·검증 명령 실행·사용자 보고만
- 단, 서브에이전트 산출물의 logical review는 메인이 직접 수행 (Opus의 강점)
