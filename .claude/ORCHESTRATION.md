# 오케스트라 운영 매뉴얼 (Opus 4.7 메인) — v2

> 사용자가 명시: "내가 24시간 답변할 수 없으니 너가 알아서 진행하고, 문제·블로커만 텔레그램으로 매일 9시에 보고해."

---

## 1. 운영 원칙 (v2 핵심)

1. **자율 진행**: 결정 사항은 메인이 합리적 추천안 기준으로 판단해서 진행. 사용자에게 매번 묻지 않음.
2. **에스컬레이션 기준**: 다음 경우에만 사용자에게 보고:
   - 비즈니스 로직상 사용자만 답할 수 있는 결정 (예: 정책·요율 기준값·법적 요구사항)
   - 외부 자격 증명 필요 (Telegram 토큰, API 키)
   - 데이터 마이그레이션이 비파괴적이지 않은 경우
   - 빌드/테스트가 풀리지 않는 블로커
3. **검증 → 시뮬레이션 → 크로스체크**: 코드 작성 후 그냥 review 하지 말고 **실제 실행/시뮬레이션**. `biz-qa-crosscheck`로 독립 교차검증.
4. **보고 채널**: 정상 진행은 PROGRESS.md 갱신만. 사용자 보고는 매일 9시 텔레그램 디제스트로 일괄.

## 2. 메뉴 → 에이전트 매핑

| 사용자 요청이 닿는 메뉴 | 호출할 에이전트 |
|---|---|
| 병의원/법인/딜러/영업사원, 코드 생성, 승인 | `biz-user-mgmt` |
| 통계 제출처, 사업자등록증 ZIP, 신규/이관, 월별 제출 | `biz-submission-routes` |
| 요율 업데이트, 코프로모션 예외 | `biz-rates-mgmt` |
| 정산내역서 업로드, 검수, 컬럼매핑 | `biz-settlement` |
| 필터링 현황·플로우, 제약사→상위법인 매핑, 법인×제약사 추가수수료 | `biz-filtering` |
| 다른 에이전트 산출물 교차검증 | `biz-qa-crosscheck` |

## 3. 6단계 워크플로우 (v2)

```
사용자 요청
   ↓
[1] 메인이 메뉴 분류 + 서브에이전트 선택 (다중 메뉴면 병렬)
   ↓
[2] 서브에이전트(들)에 mode=verify — 검증 계획 작성
   ↓
[3] biz-qa-crosscheck 호출 — 명세를 사용자 요구·기존 시스템·도메인 룰과 매칭
     - PASS 또는 CONDITIONAL_PASS → 다음 단계
     - FAIL → 작성자 에이전트에 재작성 지시 ([2]로)
   ↓
[4] 메인이 자율 결정 (사용자 미답변 항목 있으면 합리적 기본값 사용)
     - 기본값 선택은 PROGRESS.md 로그에 기록 (나중에 사용자가 보고 수정 요청 가능)
   ↓
[5] 서브에이전트에 mode=implement
   ↓
[6] biz-qa-crosscheck — 시뮬레이션·diff·회귀검증
     - PASS → 커밋·푸시 + PROGRESS.md 갱신
     - FAIL → 작성자 에이전트에 수정 지시 ([5]로)
```

**검증 통과 없이 커밋 금지. 자율 진행하되 품질 게이트는 절대 건너뛰지 않음.**

## 4. 메인이 실행할 검증 도구

| 검증 항목 | 도구 |
|---|---|
| Prisma 스키마 일관성 | `npx prisma validate` |
| TypeScript 타입체크 | `npx tsc --noEmit` (env 미비 시 부분 스킵 가능) |
| 빌드 | `npm run build` (시간 길음, blocker 의심 시만) |
| 회귀 grep | `grep -rn` 으로 영향 받는 호출부 점검 |
| API 시그니처 호환성 | 호출부 grep + diff |
| DB 마이그레이션 멱등성 | SQL의 `IF NOT EXISTS` 확인 |
| 페이지 시뮬레이션 | curl로 라우트 응답 / Node 단일 함수 실행 |

## 5. 자율 결정 시 기본값 (사용자 미답변 항목)

- **권한**: BIZ/ADMIN 모두 동일하게 (좁힐 필요 명시되면 좁힘)
- **파일 크기 제한**: Storage 기본 (50MB)
- **이력 보존**: 영구
- **소프트 vs 하드 삭제**: 데이터는 소프트 삭제(`active=false`), 파일은 하드 삭제
- **다운로드 형식**: 원본 그대로
- **드롭다운 vs 자유입력**: 마스터 데이터 있는 필드는 드롭다운 (오타 방지)
- **메뉴 이름 표기**: "거래처/유저 관리", "통계제출처 관리", "요율 관리", "정산 관리", "필터링 관리"
- **데이터 마스터**: 모든 거래처는 `/biz/clients`(병의원) 또는 `/biz/dealers`(비병의원). 다른 메뉴는 마스터를 참조만.

## 6. 텔레그램 디제스트 (구축 예정)

- 매일 9시 KST에 Vercel cron이 `/api/cron/biz-digest` 호출
- 디제스트 내용:
  - 어제 자율 진행한 작업 요약 (PROGRESS.md 로그 diff)
  - 사용자 결정 필요 항목
  - 블로커/오류
  - 배포 상태
- 사용자 답변은 텔레그램 봇 webhook이 DB에 적재 → 다음 세션에서 메인이 읽어 처리

필요 환경변수 (사용자가 제공해야 함):
- `TELEGRAM_BOT_TOKEN` — BotFather에서 받은 토큰
- `TELEGRAM_CHAT_ID_BIZ` — 사용자 본인 채팅 ID

## 8. 금지 사항 (메인)

- 검증 없이 implement 호출
- biz-qa-crosscheck 결과 무시
- DOMAIN_VIOLATION 무시
- 사용자 미확인 SQL 실제 DB에 실행 (가이드만 제공)
- 자기 합리적 기본값 + 사용자가 말한 명시적 결정 모두 무시
- 작업 결과를 채팅에 길게 늘어놓기 (간결히)

## 9. 토큰 절약

- 모든 코드 작성·읽기·수정은 서브에이전트(Sonnet)에 위임
- 메인(Opus)은 라우팅·검증 명령 실행·자율 결정·보고만
- 단, 산출물의 logical review는 메인이 직접 수행 (Opus의 강점)
- 백그라운드 에이전트 활용해 사용자 응답 대기 시간 최소화
