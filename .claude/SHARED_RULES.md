# 모든 BIZ 에이전트 공통 룰

> 사용자 명시 — 위반 시 DOMAIN_VIOLATION 보고 + 즉시 중단

## 데이터 마스터 (절대 룰)

### 거래처 등록처는 단 2곳
- **병의원** = `/biz/clients` (모델: `Client`, `UserClient`)
- **법인 / 딜러** = `/biz/dealers` (비-병의원 모든 사업자, 모델: `UserClient` with `dealerType`)

### 다른 모든 페이지는 읽기만
- 통계제출처, 정산 업로드, 요율, 필터링 등 다른 메뉴는 위 두 곳의 데이터를 **참조**만 함
- 자체 거래처/업체를 직접 추가하는 UI 만들지 말 것
- 분류·플래그·태그가 필요하면 마스터 모델에 컬럼 추가 (예: `isSettlementTarget`, `isRateTarget`)
- 이렇게 하면 데이터가 한 곳에서만 관리되어 꼬일 일이 없음

### 유저 = 3종 한정
- 병의원 / 법인 / 딜러
- 영업사원은 `User.role` 단위 (별도 거래처 X)

## 자율 진행 모드

- 사용자에게 매번 묻지 않음. 메인 추천안 기본값으로 진행
- 합리적 기본값: ORCHESTRATION.md §5 참고
- 커밋 메시지에 "사용자 자율결정 항목" 명시 (나중에 사용자가 보고 수정 요청 가능)

## 검증 게이트 (절대 스킵 금지)

- verify → biz-qa-crosscheck PASS → implement → biz-qa-crosscheck PASS → 커밋
- QA가 FAIL 주면 작성자 에이전트에 재작업 지시. 자체 무시 금지

## 메뉴 이름 표기 (확정)

- 거래처/유저 관리
- 통계제출처 관리
- 요율 관리
- 정산 관리
- 필터링 관리

## 스타일

- "매핑없음" → "컬럼 매핑 없음" 처럼 명시적으로
- 사용자가 무슨 말인지 모를 단어 쓰지 말기 (오버라이드, 시뮬레이션 등 사용 시 옆에 한글 풀이)
